# Пайплайн: имплант → 3D-модель для сайта

Обкатан на модели №1 — бедренная ножка DeltaWay™ 4# (`models/H1-deltaway-stem/`, версия 2 после
ревью) и на деталях эндопротеза ТБС со сборками (`models/hip-system/`). Список всех моделей: [MODELS.md](MODELS.md).

## Почему не AI image-to-3D

Текущий `implant.glb` на сайте сделан нейросетью по картинке (Hunyuan, `_3d-work`): форма «оплывшая»,
один запечённый атлас, 940 КБ. Импланты — промышленные детали с размерами в каталогах, их выгоднее
**строить по размерам**. Точная форма, мелкие детали геометрией, раздельные материалы, размерный ряд
меняется числами, а весит модель вдвое меньше. AI-генерацию оставляем для органики (кости), где чертежа нет.

## Схема

```
PDF-каталог + рендеры ─► 1. Спецификация  (stem_params.py: размеры, плоскости покрытий, профиль конуса)
materials/ ────────────► 2. Общая библиотека материалов (один раз на все модели)
                         3. SDF-модель (numpy) ─► marching cubes ─► эталонный меш на каждую поверхность
                         4. Blender: ремеш → удаление скрытого → проекция на SDF → срез кромок →
                            токарные детали → UV в мм → GLB ×2 LOD
                         5. gltf-transform: dedup → WebP → UV в [0,1] → quantize → meshopt
                         6. Проверка во вьюере: свет сайта + студия, крупные планы, сетка
```

Всё скриптами, ручной работы в Blender нет: `models/<id>/build.sh` — полная пересборка (~1 мин).

## Правила, выученные на модели №1

Каждое правило закрывает конкретный дефект, найденный на ревью.

### Топология
1. **Ни одной невидимой грани.** Металл под покрытием, торец шейки внутри воротника, внутренние
   крышки — удаляются. Граница удаления уходит на 0.4–0.6 мм *под* перекрывающую деталь, иначе рваный
   край выглядывает наружу (было на стыке шейки и воротника).
2. **Равномерная сетка, а не децимация.** Децимация даёт треугольники разного размера, и отражения
   на полировке ломаются по их рёбрам. Вместо неё: voxel-ремеш с шагом под LOD → проекция вершин на
   точную SDF-поверхность → тангенциальная релаксация. QuadriFlow в фоновом Blender 5.1 не
   запускается («mesh needs to be manifold» на любом меше), поэтому используется voxel-ремеш.
3. **Плотность — по материалу.** Полировка 0.62 мм (на зеркале видна каждая ошибка), напыление 0.95,
   сатин 1.0. Для LOD1 шаг ×2.
4. **Тела вращения — lathe, а не marching cubes.** Конус 12/14, воротник, канавка — точный профиль
   (s, r), аналитические нормали, острые рёбра там, где они на детали. Marching cubes давал рваную
   канавку.

5a. **Точёные детали — структурированная развёртка (`swept`), а не ремеш.** Чашка, вкладыш, головки
   и конусы — это тела вращения с острыми кромками; voxel-ремеш делает их кромки волнистыми (так было
   у вкладыша в первой сборке). `swept` — сетка «профиль × азимут», где профиль может меняться
   с азимутом (козырёк вкладыша), а **дублированный азимут с другим профилем даёт чёткую стенку**
   (пазы чашки, выступы вкладыша).
5b. **Стыкуй разные методы срезом плоскостью.** Где у точёной детали есть нетокарная часть (купол
   чашки с отверстиями), SDF-часть обрезается точной плоскостью (`bisect_keep`) там, где SDF уже
   чистая сфера, а токарный профиль доходит до той же плоскости. Обе кромки лежат на одной окружности:
   нет ни щели, ни мерцания. Резать нельзя по скруглению SDF — получается «пила».
5c. **Никаких совпадающих граней.** Две поверхности в одной плоскости мерцают (z-fighting). У чашки
   торец полированного пояска лежал в плоскости стенки напыления. Решение: поясок уходит на 0.4 мм
   под напыление.

### Кромки и переходы
5. **Граница материалов = граница мешей.** Каждая поверхность — свой меш с одним материалом.
6. **Кромка покрытия — срез плоскостью.** Покрытие строится с запасом 2 мм и обрезается точными
   плоскостями (`bisect`) → прямая чистая кромка. Ступенька 0.5 мм — отдельная полоса граней в
   плоскости среза, с плоскими нормалями.
7. **Нормали — из градиента SDF**, а не из сетки: отражения следуют истинной кривизне. Плоские
   нормали только на настоящих рёбрах (стенка ступеньки, фаски конуса).

### Сборки
5d. **Каждая деталь — отдельный узел** в GLB сборки (`stem`, `head`, `liner`, `cup`): на сайте их
   можно подписывать, анимировать (разнести эндопротез), скрывать.
5e. **В сборке удаляются контактные поверхности**, которые закрывает соседняя деталь (посадка чашки
   под вкладышем, сфера вкладыша и закрытая часть головки, конус внутри головки). Исключение —
   места, видимые сквозь отверстия. Так сборка из 4 деталей укладывается в 52k треугольников.
5f. **Мелкая резьба и рифление не моделируются геометрией** на веб-плотности: при шаге сетки 0.75 мм
   резьба превращается в шум. Либо гладко, либо картой нормалей.

### Анатомические поверхности (колено)
5g. **Сложная гладкая поверхность — одним протяжённым полем, а не склейкой примитивов.** Первая
   версия бедренного компонента была собрана из дуг, «моста» и фланца через плавное объединение:
   бугры на зеркале и паразитные плоские «диски». Правильно: корональный профиль, протянутый вдоль
   сагиттального сплайна (поле = расстояние до кривой минус профиль), параметры профиля плавно
   меняются вдоль кривой.
5g'. **Плавное объединение (`smin`) — только точных полей расстояния.** У Revistem шейка-суперэллипс
   (поле лишь приближает расстояние) давала волну в отражении на стыке с плечом; повторная нормировка
   полей (`normalize`) сделала хуже — шум градиента ушёл в нормали. Круглый конус с точным полем
   дал чистую седловину. Если сечение не круглое — лучше протяжённое поле (5g), чем `smin`.
5h. **Граница материалов по плоскостям — разрезом.** Если граница задаётся плоскостями (сторона
   кости = опилы), меш режется по ним (`split_by_planes`), и разметка граней становится точной.
   Разметка по полю с порогом даёт пунктир даже со сглаживанием.
5i. **Деталь мельче двух шагов сетки не моделируется ступенькой.** Ступенька цементного кармана
   0.8 мм при шаге 1.1 мм дробилась в пунктир. Либо пологий переход, либо карта нормалей.
5j. **SDF-сетка должна вмещать деталь с запасом.** Кончик киля вышел за границу сетки: меш
   получился незамкнутым, и ремеш перемешал ориентацию граней.

### Резьба, нити
5k. **Резьба — винтовой протяжкой.** В `swept` профиль каждого азимута — та же резьба, сдвинутая
   на `шаг × φ / 2π`: получается настоящая спираль без SDF и ремеша, ~11k треугольников на винт.
   Шлиц и канюляция — часть того же замкнутого профиля (тело — трубка, без лишних граней).
5l. **Нити и проволока — `tube` вдоль сплайна** с кадрами параллельного переноса (без закрутки).
   UV: витки по окружности × длина, под тайл плетения. Концы — срезанные, а не острые.
5m. **V в развёртках = длина по профилю**, а не высота: иначе на торцах и уступах текстура тянется
   радиальными штрихами (было на торце винта).

5n. **Винты — один генератор** `tools/screws.py` (`Screw`): осевой профиль ядра, зоны резьбы
   (`Thread`: шаг постоянный или переменный, форма гребня cortical / cancellous / fine / bio, число
   заходов), головка, шлиц (шестигранник, звезда), прорезь поперёк торца, канюляция и фичи по азимуту:
   `Notch` (самонарезающая канавка), `Flat` (лыски, пазы), `Channel` (паз под второй винт), `Blades`
   (лопасти PFNA). Им сделаны 10 винтов остеосинтеза (`models/OS-screws/`) и якоря S6–S11
   (`models/S-anchors/`). Деталь, повёрнутая наоборот (вилка XtraLoc), строится тем же `Screw` с
   прорезью на «торце» и поворачивается на 180° вокруг X: поворот, а не зеркало, не выворачивает грани. Старый
   `tools/profiles.screw_profile` остался только у GraftFix и NAVY.
5p. **Сетка резьбы привязана к спирали.** Если у всех столбцов одинаковые точки по оси, кромки
   витка пересекают сетку ступеньками, и блик на резьбе зубчатый (так было на первой версии №37).
   В зоне резьбы точки столбца на азимуте φ стоят на долях витка k/n + заходы·φ/2π, линии сетки
   идут вдоль витка. Число точек у столбцов разное, их сшивает `blender_kit.swept_zip` («молния»
   по параметру λ: равные λ дают квад, иначе треугольник). Закрывающий столбец на 2π сдвинут на
   один заход, шов идёт по спирали. Лопасти PFNA — та же спиральная сетка с нулевой высотой
   резьбы (`Blades.grid`), точки сгущены на стенках.
5q. **Стенки, которые резко меняют профиль, ставятся парой столбцов** (φ ± 1e-4): самонарезающая
   канавка — радиальный паз (`Notch`), а не хордовый срез. У хордового среза кромка гуляет по азимуту
   вместе с резьбой и рвётся на любой плотности столбцов. Так же сделана прорезь на торце. Изломы
   без ступеньки (кромка лыски, края паза) получают один столбец ровно на кромке.
5r. **Окружность UV — целое число тайлов**, иначе на шве φ = 0 / 2π виден разрыв текстуры сатина
   (`swept` и `swept_zip` округляют радиус развёртки сами; в `swept` округление добавлено 2026-10-07,
   до этого у вкладыша XPE был шов полиэтилена).
5s. **Скругление — не меньше 3–4 сегментов на 90°.** Нормали разделяются при изгибе профиля > 35°
   (`crease`). Если изгиб скругления близок к порогу и меняется по азимуту (козырёк), разделение
   включается то на одних столбцах, то на других, и на кромке видна ступенька отражения (было на входе
   вкладыша и C-Hemi). Изгибы скругления держать ≤ 28°, настоящие рёбра ≥ 40°.
5o. **Отверстия, которые целиком занимает другая деталь, не моделируются** (стержень под
   блокирующие винты): видимого отличия нет, а скрытой геометрии меньше. Часть винта внутри
   стержня удаляется.

### Материалы и UV
8. **Общая библиотека `materials/`** (`make_materials.py`): `ti_plasma_spray`, `ti_polished`,
   `ti_satin`. Тайлы бесшовные, размер тайла в мм в `materials.json`. Новые материалы (трабекулярный
   титан, керамика, полиэтилен) добавляются туда же, а не в модель. **Дописывать только в конец
   `make_materials.py`**: генератор случайных чисел общий, вставка в середину меняет текстуры всех
   материалов ниже.
9. **Напыление не должно блестеть.** Детализация лежит в альбедо и AO (стабильны при mip-уровнях),
   карта нормалей сглажена, а потерянная микро-шероховатость перенесена в roughness. Рельеф —
   перекрывающиеся капли металла, как реально ложится плазменное напыление. Трабекулярный титан
   (`ti_trabecular`, Apex 3D TF) устроен так же: решётка — нулевые линии полосового шума (коралловый
   лабиринт, поры ~0.75 мм), темнее и крупнее напыления.
10. **UV в миллиметрах.** Для покрытия и сатина — цилиндрическая развёртка вокруг оси детали
    (развёртка по окружности × высота, шов с латеральной стороны), чтобы штрихи сатина шли вдоль
    ножки, а зерно не тянулось. Для полировки — smart UV (текстура изотропная и слабая).
11. **UV квантуются.** UV в тайлах выходят за [0,1], и `quantize` их пропускает (float32 → +100 КБ).
    `tools/optimize.mjs` нормализует их в [0,1] и переносит масштаб в `KHR_texture_transform`.

### Свет
12. **Металл показывает только окружение.** В свете hero-секции сайта (серый пол, узкие полосы)
    полировка выглядит чёрным зеркалом, и это не дефект материала. Во вьюере два пресета:
    «Світло сайту» (копия `hero-model.tsx`) и «Студія» (большой верхний софтбокс, две полосы,
    тёмный пол). **Для сцен с имплантами на сайте нужен студийный свет.** Это изменение в
    `hero-model.tsx`, его согласуем отдельно.
13. **Окружение 1024 px.** При 256 (по умолчанию в PMREM) и 512 (сейчас на сайте) в зеркальной
    полировке видны квадратные тексели отражения.

## Общий код
- `tools/sdf_kit.py` — сетка SDF, примитивы, `smin`/`smax`, запись мешей и полей.
- `tools/blender_kit.py` — всё для Blender: ремеш и проекция на поле, удаление скрытого, срез с
  ребром-ступенькой, `lathe`, `swept`, `swept_outline` (профиль вдоль контура: платформы, пластины),
  `swept_zip` (столбцы с разным числом точек), `cap`, `tube`, `bisect_keep`, `split_by_planes`, UV (цилиндрическая, полярная, smart), материалы из
  библиотеки, экспорт, рендеры.
- `tools/screws.py` — генератор винтов (см. 5n–5q).
- `tools/preview_ply.py` — быстрый просмотр эталонных мешей с 6 сторон.
- `tools/optimize.mjs` — упаковка GLB.
- `materials/` — библиотека материалов (15 штук: PEEK, четыре титана (в т. ч. трабекулярный), CoCr, керамика, полиэтилен, пескоструй,
  биокомпозит, две плетёные нити, анодированный титан золотой, синий и пурпурный).

Модель H1 собрана раньше и пока использует свой скрипт; новые модели пишутся поверх `tools/*_kit.py`
(пример — `models/hip-system/`).

## Шаги

1. **Спецификация** — размерная таблица из PDF, один размер для сайта (средний: DeltaWay 4#).
   Всё в `stem_params.py`: размеры, плоскости границ покрытия, профиль токарной части, отверстия.
   Модуль импортируют и SDF-скрипт, и Blender.
2. **Материалы** — `python materials/make_materials.py` (уже есть; трогать только при новом материале).
3. **SDF** — `build_sdf.py`: лофт сечений, плавные переходы (`smin`), вычитания. Пишет эталонные меши
   по поверхностям (`*_hi.ply`) и поля (`fields.npz`) для проекции и нормалей.
4. **Blender** — `build_blender.py` (headless).
5. **Упаковка** — `tools/optimize.mjs`: LOD0 текстуры 512 px q85, LOD1 256 px q80.
6. **Проверка** — `python -m http.server 8765` в `implants-3d/`, `http://127.0.0.1:8765/viewer/`.
   В консоли браузера есть `viewer.look(target, dir, dist)`, `viewer.show(lod)`, `viewer.setEnv('site'|'studio')`
   для повторяемых крупных планов.

## Чек-лист приёмки
- [ ] Размеры совпадают с таблицей производителя.
- [ ] Силуэт совпадает с рендером производителя с 3 ракурсов.
- [ ] Режим «Сітка»: сетка равномерная, нет вытянутых треугольников, нет скрытой геометрии.
- [ ] Кромки покрытий чистые на крупном плане в LOD0 и LOD1.
- [ ] Стыки деталей (шейка/воротник и т. п.) без зазубрин и щелей.
- [ ] Отражения на полировке плавные при вращении, без изломов.
- [ ] Напыление матовое, без «блёсток», в обоих пресетах света.
- [ ] Вес и треугольники в бюджете, в консоли нет ошибок.

## Как перенести на следующую модель
1. Скопировать `models/H1-deltaway-stem/` → `models/<id>/`.
2. Для точёной детали — профиль для `lathe`/`swept` (параметры в `*_params.py`), SDF не нужен.
   Для литой/фрезерованной формы — поля в `build_sdf.py` на `sdf_kit`.
3. `build_blender.py` поверх `blender_kit`: какие поверхности, каким методом, какие материалы, шаги сетки.
4. `build.sh`, затем проверка по чек-листу во вьюере.

## Известные ограничения модели №1
- Форма сечений и границы напыления сняты с рендеров, а не с чертежа. CAD от iKey Medical даст
  точность до десятых мм.
- В LOD1 отражение на шейке на крупном плане слегка волнистое. На мобильном экране этого не видно.
- Стенка ступеньки напыления текстурирована тем же зерном. На крупном плане читается как светлый
  ободок, как на рендерах производителя.
- Сделан один размер (4#); остальные 11 — смена констант A/B/D в `stem_params.py`.
